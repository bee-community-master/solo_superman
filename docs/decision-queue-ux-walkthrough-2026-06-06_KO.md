# Decision Queue UX 실사용 점검

점검일: 2026-06-06

## 시나리오

- 아이디어: 동네 자영업자를 위한 AI 리뷰 답변 코치
- 목표: 카페와 식당 사장님이 네이버/구글 리뷰에 빠르고 정중하게 답변하고 반복 민원과 칭찬 패턴을 분석하는 SaaS의 지불 의사와 초기 검증 범위를 확인
- 경로: 온보딩에서 비즈니스 검증/강한 비즈니스 리뷰 선택, 첫 질문 생성, 질문 답변 저장 및 일괄 제출, 공개 웹 리서치 활성화 및 실행 확인

## 확인된 개선

- 공개 웹 검색 결과가 없거나 공개 URL 필터를 통과한 후보가 없을 때 provider 실패로 끝나던 문제가 재현됐다.
- 이 경우는 외부 provider 장애가 아니라 근거 부족이므로, 리서치 실행 결과를 `추가 리서치 필요` 및 품질 게이트의 `근거 부족` 상태로 남기도록 수정했다.
- 실제 UI에서 리서치 실행 카드가 `추가 리서치 필요 · 품질 확인에서 근거 부족`으로 표시되고, 리서치가 생성한 후속 질문이 노출되는 것을 확인했다.
- 후속 커밋에서 리서치 카드 제목과 질문 컨텍스트의 내부 프롬프트 문구를 줄이고, 화면 표시에는 짧은 근거 확인 제목을 사용하도록 정리했다.
- `Live Codex SDK turn execution...` 같은 runtime 내부 reason은 사용자 화면에서 한국어 상태 설명으로 변환한다.
- 질문 카드 안 동작은 `답변 저장`, 상단 배치 동작은 `저장한 답변 제출`로 분리해 사용자가 저장과 제출을 혼동하지 않게 했다.
- 공개 웹 리서치 작업 수와 실제 실행 가능 상태를 분리해, 작업이 있어도 allowlist가 꺼져 있으면 먼저 공개 웹 소스 활성화가 필요하다고 표시한다.
- 리서치 후속 질문과 출처 목록은 렌더 전에 중복을 제거하고 안정적인 key를 사용해 중복 노출과 React key 경고를 줄였다.

## 남은 UX 개선점

- 첫 질문 생성 시 18개 질문이 한 번에 만들어져 진행률과 남은 질문 수가 부담스럽다. 초반에는 핵심 질문 수를 줄이거나 `이번 라운드`와 `전체 후보`를 더 분명히 구분하는 편이 낫다.
- Codex live 질문 생성은 2분 이상 걸릴 수 있는데, 화면은 아직 세부 단계까지 보여주지는 않는다. 진행 단계, 예상 대기, 실패 시 fallback 여부가 더 필요하다.
