# Decision Queue UX 실사용 점검

점검일: 2026-06-06

## 시나리오

- 아이디어: 동네 자영업자를 위한 AI 리뷰 답변 코치
- 목표: 카페와 식당 사장님이 네이버/구글 리뷰에 빠르고 정중하게 답변하고 반복 민원과 칭찬 패턴을 분석하는 SaaS의 지불 의사와 초기 검증 범위를 확인
- 경로: 온보딩에서 비즈니스 검증/강한 비즈니스 리뷰 선택, 첫 질문 생성, 질문 답변 제출, 공개 웹 리서치 활성화 및 실행 확인

## 확인된 개선

- 공개 웹 검색 결과가 없거나 공개 URL 필터를 통과한 후보가 없을 때 provider 실패로 끝나던 문제가 재현됐다.
- 이 경우는 외부 provider 장애가 아니라 근거 부족이므로, 리서치 실행 결과를 `추가 리서치 필요` 및 품질 게이트의 `근거 부족` 상태로 남기도록 수정했다.
- 실제 UI에서 리서치 실행 카드가 `추가 리서치 필요 · 품질 확인에서 근거 부족`으로 표시되고, 리서치가 생성한 후속 질문이 노출되는 것을 확인했다.

## 남은 UX 개선점

- Codex live 질문 생성은 2분 이상 걸릴 수 있는데, 화면은 `실행 중`만 보여준다. 진행 단계, 예상 대기, 실패 시 fallback 여부가 필요하다.
- 기본 리서치 프롬프트와 카드 제목이 너무 길고 내부 문구가 그대로 노출된다. 사용자에게는 짧은 질문, 확인하려는 근거, 다음 행동만 보여주는 요약 카드가 필요하다.
- 한국어 UI 안에 `Live Codex SDK turn execution...`, `Original ambiguity`, `Collect current public...` 같은 영어 내부 문구가 섞인다.
- 첫 답변 제출 경로가 모드에 따라 다르게 느껴진다. 어떤 흐름에서는 카드의 `답변 제출` 뒤에 상단 `작성한 답변 1개 제출`이 추가로 필요해 사용자가 이미 제출했다고 오해할 수 있다.
- 로컬 질문 모드에서 답변 후 리서치 작업이 생기지만, 공개 웹 소스를 활성화하기 전에는 실행되지 않는다. 작업 수와 실행 가능 상태를 더 명확히 분리해야 한다.
- 첫 질문 생성 시 18개 질문이 한 번에 만들어져 진행률과 남은 질문 수가 부담스럽다. 초반에는 핵심 질문 수를 줄이거나 `이번 라운드`와 `전체 후보`를 더 분명히 구분하는 편이 낫다.
- 리서치 후속 질문이 중복으로 생성될 때 React key 중복 경고가 발생했다. 중복 질문 병합 또는 안정적인 고유 key가 필요하다.
