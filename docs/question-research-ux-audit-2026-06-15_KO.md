# Solo Superman 질문/리서치 UX 감사

작성일: 2026-06-15

## 목적

Solo Superman을 "기획을 상세화하는 도구"로 볼 때 핵심 경험은 사용자가 막연한 아이디어를 넣고, 이해하기 쉬운 질문에 답하고, 리서치 근거를 통해 다음 기획 판단이 선명해지는 흐름이다. 이번 감사는 개선 구현이 아니라 현재 흐름을 직접 사용해 보고 개선 방향을 정리하는 데 목적이 있다.

중점 기준은 세 가지다.

- 질문이 일반 사용자도 바로 이해할 수 있는 쉬운 말로 되어 있는가.
- 질문이 실질적으로 기획 결정을 좁히는 데 필요한가.
- 답변과 리서치 뒤에 사용자가 "내 기획이 더 구체화됐다"고 느낄 수 있는가.

## 테스트 조건

- 로컬 앱: `http://127.0.0.1:1420`
- sidecar: `http://127.0.0.1:54359`
- 기준 커밋: `8fbb721` (`origin/main`, `Improve planning questions and research flow (#509)`)
- 실행 경로: `pnpm install --frozen-lockfile`, `SOLO_LOCAL_OPEN_BROWSER=0 pnpm start:local`
- 테스트 방식: Playwright Chromium으로 실제 로컬 UI 조작
- 선택 설정: `서비스 기획 구체화`, `조금 더 자세히 묻기`, `Codex + 읽기 전용 공개 웹 리서치`
- ChatGPT Pro / Deep Research 경로: 앱의 로그인 확인 gate는 확인했으나, 현재 자동화 환경에서 사용자 Chrome/ChatGPT 로그인 세션을 사용할 수 없어 실제 Pro 계정 제출은 완료하지 못했다. 이 경계는 제품 검증의 별도 blocker로 본다.

## 샘플 아이디어

아이디어 요약:

> 동네 미용실과 네일샵 같은 소규모 매장이 전화, 카톡, 수기 장부로 따로 관리하는 예약, 대기, 쿠폰을 한 화면에서 처리하는 모바일 웹 서비스. 사장님이 노쇼를 줄이고 단골 재방문을 늘리게 한다.

목표:

> 이번 세션에서 첫 고객을 어떤 매장으로 잡을지, MVP에 꼭 필요한 기능과 첫 달 검증 실험을 정하고 싶다. 개발 전에 실제로 돈을 낼 수 있는 매장 유형과 영업 메시지를 구체화하고 싶다.

첫 답변:

> 1인 미용실과 네일샵을 먼저 보겠습니다. 전화나 카톡 예약을 놓치는 일이 바로 매출 손실로 이어지고, 사장님 혼자 일해 대기/쿠폰까지 따로 관리할 시간이 부족하기 때문입니다. 음식점 주문 확인과 단골 재방문 기능은 첫 버전 이후로 미루겠습니다.

## 관찰 요약

현재 버전은 질문/리서치의 방향성은 이전보다 좋아졌지만, 사용자가 효용을 느끼기 전에 실행 상태가 끊긴다. 특히 live 질문 생성, 공개 웹 리서치 시작, 수동 리서치 import가 모두 `blocked` 또는 `pending` 상태로 남아 핵심 가치가 완결되지 않았다.

좋았던 점:

- fallback 질문은 "소상공인 예약/주문에서 누구를 먼저 도울까요?"처럼 쉬운 말로 되어 있고, 첫 고객군을 좁히는 실질적 질문이었다.
- 선택지는 `1인 미용실/네일샵 예약 누락`, `소형 음식점 주문 확인`, `단골 재방문 관리`로 아이디어와 관련성이 있었다.
- 답변 후 다음 질문이 "그 사용자는 지금 어떤 방법으로 이 문제를 해결하고 있나요?"로 이어져 기존 대안 탐색으로 자연스럽게 넘어갔다.
- 답변 후 준비도가 0%에서 34%로 오르고, "다음에 정할 내용"과 "다음에 확인할 리서치"가 생긴 점은 기획이 진행되는 신호로 보인다.

문제였던 점:

- 첫 질문 live 생성 API는 `200`으로 끝났지만 UI는 60초 이상 "첫 질문 생성" 상태에 머물렀고, 결국 "기본 질문으로 시작"을 눌러야 했다.
- `조금 더 자세히 묻기`를 선택했는데 질문 카드에는 `차분하게 구체화`가 표시되어 설정과 결과의 연결이 불명확했다.
- 답변을 저장하면 큐는 진전되지만 `저장한 답변 제출` 버튼은 계속 비활성으로 남아 사용자가 무엇을 완료한 것인지 헷갈린다.
- 최근 활동에 `pending`, `blocked`, `accepted_with_projection` 같은 내부 상태가 그대로 보인다.
- 공개 웹 리서치 자동 시작과 수동 시작 모두 활동에는 `blocked`가 찍혔지만, 실행 카드에는 "실행 0개"가 유지되어 원인과 복구 방법을 알 수 없었다.
- 수동 리서치 결과를 붙여넣으면 "가져온 결과를 근거로 바꾸는 중"에서 멈추고, 20초 이상 대기 및 상태 새로고침 후에도 근거 매트릭스, 후속 질문, 품질 확인, 준비도 변화가 보이지 않았다.

## 질문 품질 평가

판정: 부분 합격, 단 live 생성 실패 때문에 첫 사용자 경험은 불합격에 가깝다.

### 쉬운 단어

fallback 첫 질문의 본문은 좋았다. "누구를 먼저 도울까요?", "지금 어떤 방법으로 해결하고 있나요?"는 비전문가도 이해할 수 있다.

다만 주변 UI가 어렵다. `큐`, `v7`, `실시간 업데이트 스트림`, `후속 질문 여유`, `accepted_with_projection`, `pending` 같은 말은 사용자가 기획을 하고 있다는 느낌보다 시스템 상태를 디버깅하는 느낌을 준다.

개선 방향:

- 질문 카드에는 사용자 언어만 남기고 내부 상태는 숨긴다.
- 내부 상태가 꼭 필요하면 "저장 중", "리서치 시작 실패", "다시 시도 필요"처럼 행동 가능한 표현으로 번역한다.
- 질문 방식 선택 결과를 카드에 정확히 반영한다.

### 실질적으로 필요한 질문

첫 질문은 필요했다. 이 아이디어에서 `미용실/네일샵`, `음식점`, `단골 재방문`은 서로 다른 제품이 되므로 첫 고객군을 먼저 좁히는 것은 기획 상세화에 직접 기여한다.

두 번째 질문도 필요했다. 기존 대안을 물어보는 것은 네이버 예약, 카카오 예약, POS/CRM, 수기 장부 같은 경쟁/대체재를 확인하게 만든다.

부족한 점:

- 질문이 좋은 이유는 보이지만, 답변 후 "그래서 기획서가 어떻게 바뀌었는지"가 충분히 보이지 않는다.
- "기획 반영 내용"이 한 문장으로만 보이고, 구체적 변경 전/후 diff가 없다.
- 다음 질문이 왜 우선순위 1위인지 점수나 근거가 없다.

개선 방향:

- 답변 저장 후 즉시 `정해진 것`, `아직 모르는 것`, `다음 질문 이유`를 3줄로 보여준다.
- 질문마다 "이 질문에 답하면 바뀌는 기획 항목"을 명시한다. 예: 첫 고객군, MVP 범위, 리서치 쿼리, 인터뷰 대상.
- 좋은 질문 수보다 "한 답변이 어떤 결정을 줄였는가"를 주요 성공 지표로 둔다.

### 기획 상세화 체감

답변 저장 후 준비도 34%, 다음 질문, 리서치 작업이 생긴 점은 긍정적이다. 하지만 자동 리서치와 수동 import가 막히면서 사용자는 "진짜로 기획이 발전했다"보다 "시스템이 뭔가 처리 중인데 끝나지 않는다"를 더 강하게 느낀다.

개선 방향:

- 답변 저장 직후 5초 안에 "기획 카드"를 갱신한다.
- 리서치가 막혀도 질문 루프는 계속 진행되게 하고, 리서치는 별도 recoverable task로 분리한다.
- 준비도 숫자보다 구체 산출물을 먼저 보여준다. 예: `첫 고객: 1인 미용실/네일샵`, `제외: 음식점 주문 확인`, `검증: 1인 네일샵 5곳 인터뷰`.

## 리서치 품질 평가

판정: 현재 사용자-facing 기능으로는 불합격.

### 자동 공개 웹 리서치

답변 저장 후 리서치 작업 2개가 생겼다. 하나는 `짧은 공개 검색`, 하나는 `Deep Research 요청`이었다. 그러나 자동 시작과 수동 시작 모두 활동 로그에서 `blocked`가 되었고, 실행 카드에는 실행이 0개로 남았다.

사용자가 보는 문제:

- "왜 blocked인지"가 리서치 카드 안에서 설명되지 않는다.
- "공개 웹 리서치 실행 시작" 버튼을 눌러도 실행 카드가 늘지 않는다.
- "상태 새로고침"을 눌러도 결과나 실패 원인이 분명해지지 않는다.

개선 방향:

- blocked 상태에는 반드시 원인, 사용자 조치, 재시도 조건을 한 화면에 보여준다.
- 실행 시작 버튼은 실제 실행이 만들어지지 않으면 성공처럼 보이면 안 된다.
- 리서치 작업 카드마다 `준비됨`, `실행 중`, `실패`, `결과 검토`, `기획 반영 완료`의 단계를 명확히 나눈다.

### Deep Research / ChatGPT Pro 경로

`Codex + 보이는 ChatGPT Deep Research`를 선택하면 앱은 ChatGPT 직접 로그인 확인을 요구한다. 보안 경계 자체는 맞다. 하지만 현재 자동화 환경에서는 사용자 Chrome/ChatGPT 로그인 세션이 없어 실제 Pro 계정 제출까지 검증하지 못했다.

개선 방향:

- ChatGPT Pro handoff는 "로그인 확인"만 요구하지 말고, 사용자에게 붙여넣을 프롬프트, 기대 결과 형식, 가져온 뒤 어디에 붙여넣을지를 한 화면에 보여줘야 한다.
- Deep Research 결과를 가져온 뒤에는 출처/반대 근거/불확실성/다음 질문이 실제로 생성되는지 acceptance test를 둔다.
- Pro 세션이 없을 때도 동일한 prompt preview와 수동 import dry-run을 제공해야 한다.

### 수동 리서치 import

공개 웹에서 확인한 자료를 요약해 붙여넣었다. 사용한 공개 신호는 다음과 같다.

- 카카오톡 예약하기 파트너센터: 예약 현황 조회, 확정/취소, 통계, 알림, 예약 고객 1:1 대화 기능.
- 네이버 예약/스마트플레이스 도움말: 헤어샵/네일샵 예약 제작, 검수, 실시간 예약 노출, POS/CRM 연동 가능성.
- 토스플레이스 뷰티 노쇼 글: 흩어진 예약 채널 통합, 리마인드 알림톡, 예약금 요청.
- 공비서 원장님: 네이버/전화/앱 예약 한 화면 관리, 예약금 자동화, 카카오톡 알림.
- 팅커뷰 기사: 뷰티 매장용 예약/고객관리, 예약 스케줄링, 시술 기록, 문자 발송, 1만여 고객사 주장.

이 자료로는 다음 판단이 가능했다.

- 1인 미용실/네일샵의 예약 누락과 노쇼는 실제 pain으로 볼 근거가 있다.
- 이미 강한 대체재가 많으므로 단순 예약판은 약하다.
- MVP는 "여러 채널 예약을 30초 안에 확인하고 노쇼 리마인드/예약금 요청까지 끝내는 모바일 흐름"처럼 더 좁아야 한다.
- 첫 검증은 1인 네일샵 5곳 인터뷰와 클릭형 프로토타입 지불의향 확인이 적합하다.

하지만 앱은 이 결과를 기획 카드나 다음 질문으로 즉시 바꾸지 못했다. "가져온 결과를 근거로 바꾸는 중"과 `pending` 상태가 유지되어 리서치가 실제로 무엇을 해냈는지 사용자에게 전달되지 않았다.

개선 방향:

- import 직후 "리서치가 바꾼 기획"을 보여준다.
- 예: `경쟁이 강함`, `차별화 후보`, `검증 질문`, `MVP에서 제외할 것`, `다음 사용자 인터뷰 질문`.
- 품질 gate는 내부 판정이 아니라 사용자 문장으로 보여준다. 예: "출처는 충분하지만 반대 근거가 부족합니다. 경쟁 도구의 불만 후기를 2개 더 확인하세요."

## 우선순위별 개선 방향

### P0. 첫 가치 전달을 막는 대기/blocked 상태 제거

수용 기준:

- 첫 질문 생성 클릭 후 10초 안에 질문이 보이거나, 실패 원인과 fallback 결과가 자동으로 표시된다.
- API가 성공했는데 UI가 60초 대기하는 상태가 없어야 한다.
- 공개 웹 리서치 시작 버튼을 누르면 실행 카드가 생기거나, 실패 원인이 즉시 카드에 표시된다.
- 수동 import 후 10초 안에 `기획 반영 요약`, `근거 품질`, `생성된 후속 질문` 중 최소 하나가 보여야 한다.

### P1. 질문/답변 후 기획 diff를 보여주기

수용 기준:

- 답변 저장 후 `정해진 것`, `제외한 것`, `다음에 확인할 것`이 한 화면에 보인다.
- 준비도 퍼센트보다 구체화된 기획 항목이 먼저 보인다.
- 사용자가 다음 질문을 왜 받아야 하는지 설명된다.

### P1. 리서치 결과를 결정 단위로 바꾸기

수용 기준:

- 리서치 결과 import 후 `근거`, `반대 근거`, `불확실성`, `다음 결정`이 분리되어 보인다.
- 기존 대안/경쟁 제품이 발견되면 "우리 MVP가 좁아져야 하는 지점"을 제안한다.
- 리서치가 부족하면 "무엇이 부족한지"와 "다음 검색/질문"을 제공한다.

### P2. 내부 상태 언어 제거

수용 기준:

- 일반 사용자 모드에서 `pending`, `blocked`, `accepted_with_projection`, `v7`, `큐`, `후속 질문 여유` 같은 내부 표현이 노출되지 않는다.
- 개발자/진단 모드에서만 원문 상태를 볼 수 있다.
- 최근 활동은 `답변 저장 중`, `리서치 시작 실패`, `기획에 반영됨`처럼 행동 가능한 문장으로 표시된다.

### P2. ChatGPT Pro handoff를 검증 가능한 단계로 만들기

수용 기준:

- Pro 로그인 전에도 prompt preview, 복사, 수동 import dry-run이 가능하다.
- Pro 결과를 붙여넣으면 앱이 출처/반대 근거/불확실성 gate를 통과했는지 보여준다.
- Pro 세션이 없거나 사용자가 거절해도 로컬 질문 루프와 공개 웹 리서치 경로가 막히지 않는다.

## 다음 실험 제안

다음 개선 전에 아래 acceptance test를 먼저 정의하는 것이 좋다.

1. 샘플 아이디어 입력 후 첫 질문이 10초 안에 표시된다.
2. 첫 질문은 첫 고객군, 기존 대안, 첫 검증 중 하나를 좁힌다.
3. 답변 저장 후 기획 diff가 5초 안에 표시된다.
4. 공개 웹 리서치 실행 실패 시 실패 원인과 복구 액션이 카드 안에 표시된다.
5. 수동 리서치 import 후 근거 품질과 후속 질문이 10초 안에 표시된다.
6. ChatGPT Pro handoff는 로그인 없음, 로그인 확인, 결과 import의 세 상태를 각각 검증한다.
